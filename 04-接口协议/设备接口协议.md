# 设备接口备忘


## 一张表看全

| 节点 | 用法 | 一句话说明 |
|---|---|---|
| /dev/dht11 | read 2 字节 | [0]=湿度 [1]=温度，驱动里做了校验 |
| /dev/hc_sr505 | read 阻塞 4 字节 int | 0 无人 / 1 有人，没事件就睡着等中断 |
| /dev/hc_sr04 | ioctl(fd, 0, &dist) | 距离 cm，超时 = 量程外 |
| /dev/ap3216c | ioctl GET_ALS | 特殊！见下面单独说明 |
| /dev/led | write 1 字节 | 1 亮 0 灭 |
| /dev/beep | write 1 字节 | 1 响 0 停 |
| /dev/step28byj48 | ioctl RUN | 带符号步数，正开窗帘负关，阻塞到走完 |
| /dev/sg90 | ioctl SET_ANGLE | 0~180° |

## 各个设备的细节和坑

### dht11

```c
unsigned char data[2];        /* 必须是 char！ */
read(fd, data, 2);            /* data[0]=湿度 data[1]=温度 */
```

- 两次读间隔 ≥1 秒，读失败等 1.2 秒重试就行（驱动里约 3% 概率丢边沿，正常现象）
- 校验和驱动里做过了，失败返回 -EIO，APP 收到就重试，不用自己再验
- 踩过：用 `unsigned short` 接的话读出来是 3355 这种怪数（2 字节被拼成 1 个 short 了），数据其实是对的，纯粹是接的容器不对

### hc_sr505

```c
int state;
read(fd, &state, 4);          /* 阻塞！有人=1，人走了回 0 */
```

- 阻塞是睡在驱动的等待队列上，不耗 CPU，专门开个线程挂在这上面等就行
- 用 O_NONBLOCK 打开的话没事件返回 -EAGAIN
- 模块检测到人会保持高电平约 8 秒，所以"有人"会连续报，界面做联动时注意只在新事件时动作

### hc_sr04

```c
int dist;
ioctl(fd, 0, &dist);          /* cmd 固定传 0，dist 收距离 cm */
```

- 返回 -ETIMEDOUT 就是量程外或者没接好，界面上显示 "--" 就行
- 手没挡住的时候读不到回波是正常的，下一轮就有了
- 我们用 3.3V 供电（ECHO 直连安全，不用分压），量程比标称 5V 短，1 米内有效

### ap3216c（特殊：用的是内核自带驱动）

这块板的光照传感器被出厂内核里编死的驱动占了（卸不掉，开机就抢），那个驱动只有 ioctl 没有 read——`dd if=/dev/ap3216c` 是 0 字节就是它。所以应用按它的接口来：

```c
#define AP3216C_GET_ALS _IOR('D', 1, unsigned short)
unsigned short als;
ioctl(fd, AP3216C_GET_ALS, &als);
float lux = als / 1.2;
```

自己按 61 章写过一版 read 6 字节的 ap3216c.c（IR/ALS/PS 三个 u16），实测手掌罩住 als 降、ps 升，能用；要跑自己的版本得先用 sysfs 把内置的 unbind 掉再 insmod。项目运行就用内置的 ioctl，省事。

### led / beep

```c
char v = 1;
write(fd, &v, 1);
```

- 两个都是 1 字节开关，write 完就生效
- 极性（低电平亮/响）在设备树里用 GPIO_ACTIVE_LOW 声明了，驱动里统一 0 是激活，应用层不用管极性
- write 的返回值别忽略——返回值不是 1 就说明没写进去

### step28byj48

```c
#define STEP_CMD_RUN _IOW('T', 1, int)
int steps = 2048;             /* 正=开窗帘 负=关窗帘，4096 拍=一圈 */
ioctl(fd, STEP_CMD_RUN, &steps);   /* 阻塞到走完才返回！半圈约 4 秒 */
```

- ★阻塞的，QT 里绝对不能在 UI 线程调，放独立线程跑
- 单次上限 8192 拍（驱动里防呆），Ctrl+C 能打断
- 走完驱动自动断电，不用担心线圈发热

### sg90

```c
#define SG90_CMD_SET_ANGLE _IOW('S', 1, int)
int angle = 90;
ioctl(fd, SG90_CMD_SET_ANGLE, &angle);   /* 传的是地址！ */
```

- 驱动里用 get_user 取值，所以 APP 这边传 &angle
- 连续发太快没意义，滑条拖动时限流到 100ms 发一次就够跟手了

## 通用注意事项（加新驱动时对照）

1. compatible 逗号后面千万别带空格——编译不报错、probe 静默不跑，只能 dmesg 里没打印反查（踩过两次）
2. read/write 返回实际字节数，别学某些例程 return 0
3. 设备名以 device_create 的参数为准，/dev 下叫什么看那里
4. 新加模块先全量 grep 一遍 dts 确认引脚没人用——GPIO1_IO08 是背光、UART4/UART5 其实是 I2C 总线，都是看着空闲实际有主
