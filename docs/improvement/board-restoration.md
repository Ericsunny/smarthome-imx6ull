# 开发板环境恢复与验证边界

本轮没有连接 i.MX6ULL、加载模块、改写启动配置或部署固件。Windows Qt 6.11.1 与 Linux x86_64 主机可以验证新业务核心和模拟界面；不替代以下目标环境。

## 先做只读清点

恢复到可接板时，先记录 `uname -a`、实际 DTB/启动方式、`/proc/device-tree/model`、模块和应用哈希、Qt 版本、动态库依赖、设备节点及占用者。旧资料的平台是 ATK-i.MX6ULL、Linux 4.1.15、Qt 5.12.9，但当前板端状态未知。

本机较新整机目录、Git 基准和本轮工作目录是三份不同来源；见 `00-baseline` 指纹。VM 中本轮使用的是 Linux 5.4 x86_64 主机构建环境，并没有恢复 ARM BSP/SDK。Windows 注册表中的 Qt 5.14.2 路径已失效，实际可用的工具链是 Qt 6.11.1/MinGW 13.1。

## 最小依赖

新主程序只需 C++11、线程库和 Qt Widgets。Qt 6 原生构建需 C++17；Qt 5 构建配置保持 C++11。OpenCV、SeetaFace、SQLite、摄像头及网络服务不属于新主程序依赖。

Qt 5.12.9 与 ARM 工具链的完整编译尚待验证。先用本机 Qt Creator 打开 `app/smarthome.pro` 运行 `--simulate`，也可用 CMake；目标 Linux 构建使用相同核心代码与 Linux 设备后端。

## 接口核对

| 节点 | 当前主程序使用的契约 | 恢复后要核对 |
|---|---|---|
| dht11 | 一次 read 返回湿度/温度两个字节；驱动负责校验与超时 | 实际驱动版本、采样间隔、错误码、单次最长返回时间 |
| ap3216c | BSP `_IOR('D',1,unsigned short)` ioctl；原始值 /1.2 为估算 | 内建驱动 ABI，不能加载另一版本后假设兼容；没有计量标定 |
| hc_sr505 | 单读取者、首次电平快照、poll/read、空读 EAGAIN | 必须核对本轮驱动；旧驱动缺 .poll，应用会报告 EPROTO 并退避 |
| led/beep | 单字节 0/1 命令；报告写接口结果 | 电平极性与实际物理动作；写成功不等于实物已测 |
| sg90 | `_IOW('S',1,int)` 设置角度并启用 PWM；`_IO('S',2)` 停用；probe 不主动居中 | 须使用本轮驱动；20ms 周期及实际可用角度/机械限位；配置/启用错误传播与停用后波形 |
| step28byj48 | `_IOW('T',1,int)` 带符号相对步数、最大 ±8192；执行完/中断后线圈断电 | IN1~4 顺序、方向、负载/行程标定、信号中断后的 EINTR、无自动重放；无位置反馈 |

`tools/pir_contract.c` 只读输入，可编译后在保持输入稳定的条件下运行，核对首次快照、单读者 EBUSY、空闲 poll 超时和 EAGAIN。本轮只编译了工具，没有执行硬件契约测试。

## 顺序与停止条件

1. 备份当前应用/模块并核对哈希，确认现场业务与引脚占用；先用独立路径测试，不覆盖现役程序。
2. 在匹配的 Linux 4.1.15 BSP 编译模块与 Qt 5 应用，再核对传输两端哈希。
3. 先逐个输入，再验证撤防/布防/静音/故障/恢复和物理输出。PIR 高电平保持时间来自模块，应另测。
4. DHT11 正常、校验失败、超时下，分别记录采样成功率与光照最大更新间隔；输出故障不发布动作已成功。
5. 在空闲和采集中正常退出、重新打开设备。主机的 stop 测试使用可取消替身；真实内核如果不返回，应用无法承诺硬性退出期限。

执行器验证另按以下顺序：先机构脱开/无负载确认 PWM 与相序，再安装并标定可用角度和帘体总行程。确认程序/模块启动不主动移动、手动接管和输入失效暂停有效；人为中断步进后参考位必须未知，不能重试累计步数。用忙碌步进并发采集测量光照最大更新间隔及 UI 响应，单独观察退出时 PWM/线圈状态。

默认 0/90°、2048 半步及光照 30/80 都是待标定参数；没有机械校准、载荷与窗侧传感器布置证明前，不在装配机构上直接启用自动。通风收益还取决于外侧空气和风压，不能用程序超限解除计数代替温湿度改善对照测量。

出现新的 Oops、持续 D 状态或 GPIO/电气异常时保存日志并停测。部署镜像、变更 DTB 或受控重启需要根据已核实环境制定方案，不能直接套用历史命令。
